# 任务分工

本文档用于给团队成员快速说明当前项目状态，以及不同类型改动应该落到哪些文件。

## 当前项目入口

```text
LiveSH/
├── backend/app/
├── frontend/src/
├── data/
└── docs/
```

## 1. 指标与算法负责人

主要文件：

```text
backend/app/process_data.py
backend/app/metrics.py
backend/app/poi_taxonomy.py
backend/app/models.py
```

重点负责：

- POI 分类和供给权重
- 区级、街镇级聚合
- 稳健评分 `livability_score_v2`
- 可达性、E2SFCA、生活圈评分
- `calibrated_score_life_circle` 的定义和解释

修改后通常需要：

```bash
cd backend
python3 -m app.process_data
```

如果字段结构变化，还需要同步：

```text
backend/app/schemas.py
frontend/src/types/metrics.ts
```

## 2. 后端接口负责人

主要文件：

```text
backend/app/main.py
backend/app/schemas.py
backend/app/database.py
```

当前核心接口：

- `/api/summary`
- `/api/districts`
- `/api/streets`
- `/api/amap/shanghai-districts`
- `/api/amap/shanghai-streets`
- `/api/ai/advice`

验收重点：

- 返回字段与前端类型保持一致
- 排序逻辑与默认推荐指标一致
- 新增字段后接口文档同步更新

## 3. 前端可视化负责人

主要文件：

```text
frontend/src/App.tsx
frontend/src/components/MapPanel.tsx
frontend/src/components/StatsPanel.tsx
frontend/src/components/StreetPanel.tsx
frontend/src/components/ChartsPanel.tsx
```

重点负责：

- 地图专题切换
- 区域与街镇详情展示
- 图表内容与联动
- 当前推荐指标和页面文案保持一致

验收重点：

- 区级和街镇级交互都能正常使用
- 图表中的字段与当前模型一致
- 页面不再混用旧版“简单宜居评分”叙事

## 4. 数据负责人

主要文件与目录：

```text
data/README.md
data/sh_house_dataset_raw.parquet
data/sh_poi_raw/
data/sh_street_boundary/
```

重点负责：

- 原始数据准备
- 街镇边界完整性
- 派生结果检查
- 17w 房源扩展数据的准备与地理编码

## 5. AI 建议负责人

主要文件：

```text
backend/app/ai_advice.py
frontend/src/components/AIAdvicePanel.tsx
```

当前状态：

- 前后端链路已经打通
- 后端仍返回规则占位文本
- 后续可增加 `LLM_API_KEY`、`LLM_BASE_URL`、`LLM_MODEL` 等配置并接入真实模型

验收重点：

- 返回结构仍兼容现有前端
- 建议内容能引用当前指标，而不是脱离数据空谈
- 保留“数据局限”说明，避免把模型结果说得过满

## 6. 文档负责人

需要同步维护：

```text
README.md
docs/*.md
data/README.md
```

特别注意不要再把以下旧说法当作当前默认逻辑：

- “项目只做区级分析”
- “推荐区域按 `livability_score` 排序”
- “街道级分析是未来扩展”

当前默认主线应统一为：

```text
三层分析 + 供需可达性 + 生活圈 + 校准评分
```
