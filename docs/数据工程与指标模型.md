# 数据工程与指标模型

本文档说明 LiveSH 当前的数据输入、清洗流程、空间匹配过程和多阶段评分模型。

## 输入数据

房价数据：

```text
data/sh_house_dataset_raw.parquet
```

POI 数据：

```text
data/sh_poi_raw/
```

街镇边界：

```text
data/sh_street_boundary/shanghai_street_boundary.shp
```

POI 当前使用类别：

- 购物
- 医疗
- 交通
- 休闲娱乐
- 公司企业
- 住宅

其中住宅 POI 主要用于需求代理和供需分析，不直接进入服务设施加分项。

## 清洗与入库流程

后端脚本：

```text
backend/app/process_data.py
```

主要步骤：

1. 读取房源 parquet、POI shapefile 和街镇边界
2. 删除关键字段缺失或坐标异常的数据
3. 对房源和 POI 去重
4. 统一行政区名称
5. 将房源和 POI 匹配到街道/镇
6. 统一处理 WGS84 与 GCJ-02 坐标
7. 生成区级和街镇级聚合指标
8. 计算房源点周边可达性、设施供需充足度和生活圈特征
9. 写入数据库，同时输出派生审计文件
10. 可选执行展示分脚本，补充 0-10 展示用分数字段

默认数据库为：

```text
backend/livability.db
```

派生结果写入：

```text
data/derived/
```

展示用分数可通过以下脚本补齐或更新：

```bash
cd backend
python3 -m app.update_display_scores
```

该脚本会为区级和街镇级表补充 `*_display` 字段，并在修改 SQLite 数据库前生成备份。

## 坐标一致性

- 原始空间分析主要基于 WGS84
- 高德地图展示统一使用 GCJ-02
- 房源入库时会保留并转换两套坐标
- POI 同时保留 WGS84 与 GCJ-02 字段

## 指标层次

### 1. 基础聚合指标

区级和街镇级都会生成：

- 平均挂牌单价 `avg_price`
- 平均挂牌总价 `avg_total_price`
- 房源数量 `house_count`
- 各类 POI 数量
- POI 总量 `poi_total`
- 商圈活跃度 `business_activity`

商圈活跃度：

```text
business_activity =
  购物 * 0.35 +
  交通 * 0.25 +
  医疗 * 0.15 +
  休闲娱乐 * 0.15 +
  公司企业 * 0.10
```

### 2. Phase 1：稳健评分

在基础聚合之上，系统进一步计算：

- POI 多样性 `poi_diversity`
- 各类服务的每房源供给强度
- 房价压力 `cost_pressure`
- 房价负担分 `affordability_score`
- 服务分 `service_score`
- 活力分 `vitality_score`
- 稳健评分 `livability_score_v2`

这一层用于替代早期过于简单的：

```text
livability_score = 标准化(商圈活跃度) - 标准化(平均房价)
```

后者仍保留在库中，主要用于历史对照。

### 3. Phase 2：房源点可达性

围绕每个房源点计算：

- 各类设施的距离衰减可达性
- 最近交通距离
- 最近医疗距离
- 综合可达性分 `access_score`
- 性价比分 `value_score`

### 4. Phase 4：E2SFCA 设施供需充足度

系统会基于房源点与住宅 POI 构造需求点，并计算：

- `shopping_e2sfca_access`
- `traffic_e2sfca_access`
- `healthcare_e2sfca_access`
- `recreation_e2sfca_access`
- `company_e2sfca_access`
- `e2sfca_access_score`
- `e2sfca_value_score`
- `sample_reliability_score`
- `calibrated_score`

样本可信度会对小样本结果进行降权，避免极少量房源把排名推得过高。

### 5. 生活圈评分

系统按 5 / 10 / 15 分钟生活圈分别计算：

- 覆盖率
- 加权可达性
- 设施多样性
- 分项生活圈得分

最终得到：

- `life_circle_5min_score`
- `life_circle_10min_score`
- `life_circle_15min_score`
- `life_circle_score`
- `calibrated_score_life_circle`

当前前端默认推荐排序、地图默认评分和榜单展示，均以 `calibrated_score_life_circle` 为主。

### 6. 展示分字段

数据库中保留原始模型分，同时也可包含 `*_display` 展示字段：

- 线性 0-1 分数通常映射为 0-10
- `livability_score`、`calibrated_score`、`calibrated_score_life_circle` 等相对分使用鲁棒 sigmoid 映射到约 4-9 的展示区间

前端优先展示 `*_display` 字段；缺失时回退到原始分。

## 真实路网步行试算

`backend/app/sample_walking_routes.py` 用于对指定街镇或行政区抽样房源，调用高德步行路线规划，重算路线版生活圈。

常用命令：

```bash
cd backend
python3 -m app.sample_walking_routes --district 杨浦 --street 五角场街道 --max-api-calls 252
python3 -m app.sample_walking_routes --district 杨浦 --all-streets --max-api-calls 3024 --output-prefix yangpu_all
```

主要输出：

```text
data/cache/amap_walking_route_cache.jsonl
data/derived/amap_walk_compare_yangpu_all.csv
data/derived/amap_walk_life_circle_street_metrics_yangpu_all.csv
```

后端接口 `/api/streets/route-life-circle/yangpu` 会读取这些输出，供前端街镇图表展示。该流程目前是杨浦试算，不改变全市默认 `calibrated_score_life_circle`。
