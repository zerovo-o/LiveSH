# 数据工程与指标模型

本文档说明 LiveSH 的输入数据、清洗流程、坐标处理、区级聚合指标和宜居性评分模型。

## 输入数据

房价数据：

- 文件：`data/anjuke17w/dataset.csv`
- 关键字段：标题、区、街道、小区、价格、小区均价
- 坐标来源：通过高德 Web 服务 API 按小区名/区名/街道名地理编码补齐 GCJ-02，并反算得到 WGS84

POI 数据：

- 目录：`data/sh_poi_raw/`
- 数据格式：shapefile
- 当前使用类别：
  - 购物
  - 医疗
  - 交通
  - 休闲娱乐
  - 公司企业
  - 住宅

## 清洗与入库

后端脚本：`backend/app/process_data.py`

主要处理步骤：

1. 读取房价 CSV 与 POI shapefile。
2. 删除关键字段为空的数据。
3. 统一行政区名称，例如将不同来源中的区名标准化为同一套区级名称。
4. 过滤 `上海周边` 等非上海区域。
5. 通过高德 API 按小区名/街道名/区名地理编码，得到 GCJ-02 坐标。
6. 将 GCJ-02 反算为 WGS84，保留两套坐标。
7. 按区级和街道级聚合生成指标。
8. 写入数据库。

默认数据库为 SQLite：`backend/livability.db`。如配置 `DATABASE_URL`，可切换到 PostgreSQL。

## 坐标一致性

高德地图使用 GCJ-02 坐标。为避免地图底图、行政区边界和点位发生偏移，本项目约定：

- 前端地图展示统一使用 GCJ-02。
- 房价原始坐标按 WGS84 读取，入库时转换为 GCJ-02。
- POI 数据同时保留 WGS84 与 GCJ-02 字段，前端和区级中心点使用 GCJ-02。

## 区级聚合指标

每个区生成以下核心指标：

- 平均挂牌单价 `avg_price`
- 平均挂牌总价 `avg_total_price`
- 房源数量 `house_count`
- POI 总数 `poi_total`
- 购物 POI 数 `shopping_count`
- 交通 POI 数 `traffic_count`
- 医疗 POI 数 `healthcare_count`
- 休闲娱乐 POI 数 `recreation_count`
- 公司企业 POI 数 `company_count`
- 住宅 POI 数 `residence_count`
- 商圈活跃度 `business_activity`
- 宜居性评分 `livability_score`

## 商圈活跃度

商圈活跃度由购物、交通、医疗、休闲娱乐与公司企业 POI 加权得到：

```text
business_activity =
  购物 * 0.35 +
  交通 * 0.25 +
  医疗 * 0.15 +
  休闲娱乐 * 0.15 +
  公司企业 * 0.10
```

住宅 POI 目前用于区域详情展示和辅助理解，不直接进入商圈活跃度公式。

## 标准化与评分

不同指标量纲不同，因此使用 Min-Max 标准化：

```text
X' = (X - min) / (max - min)
```

综合评分：

```text
livability_score = 标准化(商圈活跃度) - 标准化(平均单价)
```

解释：

- 商圈活跃度越高，评分越高。
- 平均房价越高，评分越低。
- 分数越高，表示区域在当前模型下更接近“生活便利 + 居住成本相对合理”。
