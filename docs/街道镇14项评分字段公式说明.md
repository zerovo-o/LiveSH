# 街道/镇精细分析 14 项评分字段与区级评分公式

本文整理前端“街道/镇精细分析”面板中，除“最近交通”和“最近医疗”两个最近地点模块以外的 14 个数值字段，并补充区级评分的介绍与公式。

对应前端位置：`frontend/src/components/StreetPanel.tsx`  
核心算法文件：`backend/app/metrics.py`  
真实步行路线升级脚本：`backend/app/sample_walking_routes.py`

## 0. 通用符号

### 0.1 MinMax 归一化

项目中大量字段会先做 MinMax 归一化：

```text
minmax(x_i) = (x_i - min(x)) / (max(x) - min(x))
```

如果同一批数据里最大值等于最小值，则统一返回 `0.5`。

### 0.2 百分位排名

价格负担分使用百分位排名：

```text
percentile_rank(x_i) = (rank(x_i) - 1) / (N - 1)
```

其中 `rank` 为从低到高排序后的平均名次。

### 0.3 距离衰减

原始空间距离口径：

```text
decay = exp(-distance_m / beta_m)
```

真实步行路线升级口径：

```text
decay_route = exp(-walking_duration_min / beta_min)
```

生活圈路线版中：

```text
beta_min = life_circle_minutes / 2
```

也就是 5 分钟圈 `beta=2.5`，10 分钟圈 `beta=5`，15 分钟圈 `beta=7.5`。

## 1. 校准评分

前端名称：校准评分  
后端字段：`calibrated_score_life_circle`

含义：街道/镇的最终推荐评分。它综合基础宜居、设施供需充足度、生活圈、性价比，并乘以样本可信度和生活圈强化系数。

公式：

```text
base_score =
  0.30 * livability_score_v2
+ 0.30 * e2sfca_access_score
+ 0.30 * life_circle_score
+ 0.10 * value_score

calibrated_score_life_circle =
  base_score
* sample_reliability_score
* (0.6 + 0.4 * life_circle_score)
```

其中：

```text
livability_score_v2 =
  0.72 * service_score
+ 0.20 * vitality_score
+ 0.08 * affordability_score
```

真实步行路线升级后，对应比较文件中的路线版字段为：

```text
calibrated_score_life_circle_route =
  base_score_route
* sample_reliability_score
* (0.6 + 0.4 * life_circle_score_route)
```

## 2. 区级评分

前端位置：区级总览、地图区级弹窗、图表区级排名  
后端表：`district_metrics`  
后端模型：`DistrictMetric`  
核心字段：`calibrated_score_life_circle`

含义：区级评分是行政区层面的最终综合推荐分，例如黄浦、杨浦、徐汇等区的整体宜居评分。它与街道/镇校准评分使用同一套权重和公式，区别在于数据聚合维度不同：

```text
区级评分聚合维度 = ["district"]
街道/镇评分聚合维度 = ["district", "street"]
```

也就是说，区级评分会先把同一区内的房源、POI、生活圈、设施供需充足度等指标按区聚合，再计算区级综合分；街道/镇评分则是在区 + 街道/镇这个更细粒度上计算。

区级基础宜居分：

```text
district_livability_score_v2 =
  0.72 * district_service_score
+ 0.20 * district_vitality_score
+ 0.08 * district_affordability_score
```

其中：

```text
district_service_score =
  0.25 * minmax(shopping_per_house)
+ 0.25 * minmax(traffic_per_house)
+ 0.20 * minmax(healthcare_per_house)
+ 0.15 * minmax(recreation_per_house)
+ 0.15 * minmax(poi_diversity)

district_vitality_score =
  0.40 * minmax(company_per_house)
+ 0.30 * minmax(poi_total)
+ 0.30 * minmax(business_activity)

district_affordability_score =
  1 - percentile_rank(log(avg_price))
```

区级最终校准评分：

```text
district_base_score =
  0.30 * district_livability_score_v2
+ 0.30 * district_e2sfca_access_score
+ 0.30 * district_life_circle_score
+ 0.10 * district_value_score

district_calibrated_score_life_circle =
  district_base_score
* district_sample_reliability_score
* (0.6 + 0.4 * district_life_circle_score)
```

其中各区级输入项的来源为：

```text
district_e2sfca_access_score = 区内房源设施供需充足度聚合后再归一化合成
district_life_circle_score = 区内房源 life_circle_score 的平均值
district_value_score = 区内房源 house_value_score 的平均值
district_sample_reliability_score = clip(district_house_count / 50, 0, 1)
```

区级评分和街道/镇评分的关系：

```text
相同点：使用同一套评分公式、权重、归一化和样本可信度逻辑
不同点：区级按 district 聚合，街道/镇按 district + street 聚合
```

因此，区级评分适合比较“哪个行政区整体更宜居”，街道/镇评分适合比较“同一区内部哪些街镇更优”。

## 3. 生活圈总分

前端名称：生活圈总分  
后端字段：`life_circle_score`

含义：综合 5 分钟、10 分钟、15 分钟三个生活圈层级后的总分。

公式：

```text
life_circle_score =
  0.40 * life_circle_5min_score
+ 0.35 * life_circle_10min_score
+ 0.25 * life_circle_15min_score
```

街道/镇层面取区域内房源的平均值：

```text
street_life_circle_score = mean(house_life_circle_score)
```

真实步行路线升级后，对应字段为：

```text
life_circle_score_route =
  0.40 * life_circle_5min_score_route
+ 0.35 * life_circle_10min_score_route
+ 0.25 * life_circle_15min_score_route
```

## 3.1 商圈活跃度指数

前端名称：商圈活跃度指数  
后端字段：`business_activity`

含义：商圈活跃度指数是五类 POI 数量的加权和，用于描述区域配套与商业活动的原始规模。它不是 0-1 评分，也不是 10 分制展示分，因此在 POI 数量较多的区或街道/镇中可能达到几百、几千。

公式：

```text
business_activity =
  0.35 * shopping_count
+ 0.25 * traffic_count
+ 0.15 * healthcare_count
+ 0.15 * recreation_count
+ 0.10 * company_count
```

对应中文口径：

```text
商圈活跃度指数 =
  购物 POI 数 * 0.35
+ 交通 POI 数 * 0.25
+ 医疗 POI 数 * 0.15
+ 休闲娱乐 POI 数 * 0.15
+ 公司企业 POI 数 * 0.10
```

随后会对 `business_activity` 做 MinMax 归一化，得到：

```text
activity_norm = minmax(business_activity)
```

`activity_norm` 才是 0-1 标准化结果，可在前端按百分比展示。`business_activity` 本身继续保留原始指数含义。

## 4. 5 分钟基础生活

前端名称：5分钟基础生活  
后端字段：`life_circle_5min_score`

含义：衡量每套房源 5 分钟生活圈内基础日常服务的覆盖、可达和多样性。

5 分钟基础生活包含 4 类 POI：

```text
convenience_store
supermarket
bus_stop
pharmacy
```

参数：

```text
空间距离半径 = 320m
空间距离 beta = 160m
覆盖率权重 = 0.45
可达性权重 = 0.35
多样性权重 = 0.20
```

公式：

```text
life_circle_5min_score =
  0.45 * life_circle_5min_coverage
+ 0.35 * minmax(life_circle_5min_access)
+ 0.20 * life_circle_5min_diversity
```

真实步行路线升级后：

```text
life_circle_5min_access_route =
  sum(supply_weight_j * exp(-walking_duration_min_j / 2.5))
```

并继续使用同样的覆盖、可达、多样性权重。

## 7. 5 分钟覆盖率

前端名称：5分钟覆盖率  
后端字段：`life_circle_5min_coverage`

含义：5 分钟基础生活所需 POI 类型中，有多少类型能被该房源覆盖。

房源级公式：

```text
life_circle_5min_coverage =
  covered_subtype_count / required_subtype_count
```

5 分钟基础生活 `required_subtype_count = 4`。

街道/镇层面：

```text
street_life_circle_5min_coverage =
  mean(house_life_circle_5min_coverage)
```

真实步行路线升级后，`covered_subtype_count` 的判断从“空间距离在 320m 内”改为“最快候选 POI 的步行时间 <= 5 分钟”。

## 10. 样本可信度

前端名称：样本可信度  
后端字段：`sample_reliability_score`

含义：用于降低样本量不足区域的最终评分。房源样本越多，可信度越高，达到阈值后封顶为 1。

公式：

```text
sample_reliability_score =
  clip(house_count / reliability_house_threshold, 0, 1)
```

其中：

```text
clip(x, 0, 1) 表示把数值限制在 0 到 1 之间
```

该字段会直接乘到校准评分中：

```text
calibrated_score_life_circle ∝ sample_reliability_score
```

## 11. 设施供需充足度

前端名称：设施供需充足度  
后端字段：`e2sfca_access_score`

含义：使用 E2SFCA 方法，衡量设施供给对周边居住需求的充足程度。它不仅看设施近不近，也看设施是否被周边需求竞争。

第一步，计算每个设施的供给比：

```text
facility_supply_ratio =
  1 / sum(demand_weight_i * exp(-distance_i / beta))
```

第二步，计算房源能获得的设施供给：

```text
house_category_e2sfca_access =
  sum(facility_supply_ratio_j * exp(-distance_j / beta))
```

房源级设施供需充足度：

```text
house_e2sfca_access_score =
  0.25 * minmax(shopping_e2sfca_access)
+ 0.25 * minmax(traffic_e2sfca_access)
+ 0.20 * minmax(healthcare_e2sfca_access)
+ 0.15 * minmax(recreation_e2sfca_access)
+ 0.15 * minmax(company_e2sfca_access)
```

街道/镇层面先对五类房源设施供需充足度取均值，再重新归一化合成：

```text
e2sfca_access_score =
  0.25 * minmax(mean(shopping_e2sfca_access))
+ 0.25 * minmax(mean(traffic_e2sfca_access))
+ 0.20 * minmax(mean(healthcare_e2sfca_access))
+ 0.15 * minmax(mean(recreation_e2sfca_access))
+ 0.15 * minmax(mean(company_e2sfca_access))
```

## 12. 房价负担分

前端名称：房价负担分  
后端字段：`affordability_score`

含义：衡量街道/镇平均房价的相对负担水平。房价越低，分数越高；房价越高，分数越低。

公式：

```text
cost_pressure = percentile_rank(log(avg_price))

affordability_score =
  1 - cost_pressure
```

其中 `avg_price` 是区域平均单价，使用对数是为了降低极端高价对排序的影响。

## 13. POI 多样性

前端名称：POI多样性  
后端字段：`poi_diversity`

含义：衡量区域内五类服务 POI 的结构是否均衡。只集中在一种服务上，多样性较低；五类服务分布越均衡，多样性越高。

五类服务：

```text
购物
交通
医疗
休闲娱乐
公司企业
```

公式使用归一化熵：

```text
p_i = count_i / sum(count_i)

poi_diversity =
  - sum(p_i * log(p_i)) / log(K)
```

其中 `K=5`。如果区域内没有 POI，则多样性为 `0`。

## 14. 可达性分

前端名称：可达性分  
后端字段：`access_score`

含义：基于房源到五类服务 POI 的距离衰减，衡量房源周边服务接近程度，并在街道/镇层面取平均。

房源到某类服务的可达性：

```text
category_access =
  sum(exp(-distance_m / beta_m))
```

五类参数：

```text
购物: 半径 1000m, beta 500m
交通: 半径 800m, beta 400m
医疗: 半径 2000m, beta 1000m
休闲娱乐: 半径 1500m, beta 750m
公司企业: 半径 2000m, beta 1000m
```

房源级可达性分：

```text
house_access_score =
  0.25 * minmax(shopping_access)
+ 0.25 * minmax(traffic_access)
+ 0.20 * minmax(healthcare_access)
+ 0.15 * minmax(recreation_access)
+ 0.10 * minmax(company_access)
+ 0.05 * minmax(poi_diversity_around_house)
```

街道/镇层面：

```text
access_score =
  mean(house_access_score)
```

## 15. 性价比分

前端名称：性价比分  
后端字段：`value_score`

含义：街道/镇内房源“服务可达性”和“价格友好度”的综合价值分。

房源级价格友好度：

```text
house_affordability_score =
  1 - percentile_rank(log(unit_price))
```

房源级性价比分：

```text
house_value_score =
  0.80 * house_access_score
+ 0.20 * house_affordability_score
```

街道/镇层面：

```text
value_score =
  mean(house_value_score)
```

## 17. 与两个最近地点模块的区别

本文未纳入的两个字段：

```text
nearest_traffic_distance
nearest_healthcare_distance
```

它们只是“最近交通”和“最近医疗”的距离展示字段，算法上取的是区域内房源最近距离的中位数：

```text
street_nearest_traffic_distance = median(house_nearest_traffic_distance)
street_nearest_healthcare_distance = median(house_nearest_healthcare_distance)
```

这两个字段不参与本文 14 项评分公式的逐项介绍。
